# Finquanta — Design-to-Section Mapping Guide

*Reconciled from 38 reference plates, 8 cluster mappings, 8 adversarial critiques and one coherence review. Every match below is final. Where a critique overturned an earlier proposal, the row says so.*

---

## 1. The verdict

**Eight plates form the backbone, and they are laws applied to shared components — not references pinned to pages.** The single largest defect in the prior work was mapping by page cluster when the codebase is built from shared primitives: `CtaBand` (~25 routes) collected 13 competing plates, `PageHero` (18 routes) collected 14, `FaqAccordion` (10 routes) collected 7 — implementing that would fork six components twenty ways and destroy the family reading the whole exercise depends on. The backbone is **S35** (chrome as discrete objects; state is inversion, never tint), **S18** (label chip opens a card, circular ↗ closes it — the only tool in the corpus for making N unrelated blocks read as one system), **S38** (eyebrow left / lead centre / action right — the section header for ~40 bands), **S16** (value ≥ 2.5× its label; exactly one accented cell per view), **S11** (hairline label/value rows, no boxes, no icons, the figure inside the CTA), **S36** (iconless lists — bold label over a grey sub-line), **S12** (unequal tiles, one invariant gutter, one typographic cell), and **S15** (notched sheet, and concave geometry lives *only* on the overlay plane). Eleven further plates survive as one-off accents used exactly once each, and nine are traps for this site and are forbidden. Two things gate the whole programme and are not design problems: the placeholder audit (33 invented records, fabricated award issuers, a malformed phone number, a personal gmail on a partner site, four dead routes), and a fixed asset budget (3 screenshots, 3 photographs, 12 logo SVGs, 1 portrait, 2 certificate scans) — everything in the build order below ships with **zero** new assets.

## 2. The reconciled token set

```css
/* ─── SURFACES — four, and only four ─────────────────────────────────── */
--ground:        #FBF7F0;  /* page body. the default. */
--surface:       #FFFFFF;  /* cards, panels, sheets */
--band:          #F6F0E4;  /* the ONLY alternating band tint. retire the third cream. */
--ink:           #2E1B45;  /* inversion. max THREE ink surfaces per scroll. */

/* ─── TEXT ───────────────────────────────────────────────────────────── */
--ink-900:       #2E1B45;  /* headings on light                    13.0:1 on ground */
--ink-700:       #4A2C6B;  /* ALL body copy on light               ~8.9:1 on ground */
--ink-500:       #6E5485;  /* captions/metadata on LIGHT ONLY       6.0:1 on ground
                              NEVER on ink — that pairing is 2.41:1, the site's worst bug */
--cream-200:     #EDE3D5;  /* ALL text on ink                      12.18:1 on ink */
/* --ink-300 #A38EBC — DELETE. 5.26:1 bare, but ~3.5:1 over BandArt's
   gradient, and its only current use is text-on-ink. Replace with cream-200. */

/* ─── ACCENT — the law that resolves six conflicting corpus rules ─────
   Plum is the light-ground accent and means STATE/SELECTION.
   Sand is the dark-ground accent and means PROOF/EMPHASIS.
   Exactly one accented element per viewport. Nothing else is ever coloured. */
--plum:          #7A4FB0;  /* active item, selected chip, primary button, the one flooded cell
                              5.18:1 on ground · white on plum 5.88:1 · cream on plum 5.50:1 */
--plum-100:      #EEE0F5;  /* HOVER ONLY. not an icon-chip fill — that treatment is deleted */
--sand:          #E8C89B;  /* the single high-luminance anchor on any dark band
                              9.7:1 with ink · ink-on-sand 9.69:1 */
--sand-100:      #F5E4C7;  /* credential pill fill on light; ink-700 on it = 9.02:1 */
--violet:        #B99AD6;  /* ink on violet 6.37:1. NEVER cream on violet — 2.27:1, fails. */

/* ─── STATUS — semantic only, never decorative (S14 law) ─────────────── */
--success:       #3D8B5C;  /* LIVE STATE ONLY. 4.16:1 on white — fails AA for body.
                              Permitted on chips ≥18.66px bold, or paired with a text label.
                              Never means "included". Never a tick. */
--warning:       #9A4F1E;  /* was #C26A2E = 3.43:1 on band, FAILS. Corrected: 5.32:1.
                              Form errors only, ≥14px. */

/* ─── LINES ──────────────────────────────────────────────────────────── */
--hairline-light: 1px solid rgb(46 27 69 / .10);   /* on ground/surface/band */
--hairline-dark:  1px solid rgb(237 227 213 / .15); /* on ink */
/* cream-200 as a border on cream is ~1.2:1 — invisible. That is why the policy TOC
   rules and half the card edges disappear. Retire it as a border token entirely. */

/* ─── RADIUS — five steps, each bound to one job ─────────────────────── */
--r-button:      10px;   /* buttons. rectangles are buttons, pills are tags (S24 law). */
--r-card:        16px;   /* cards, panels, banners */
--r-surface:     24px;   /* full bands, large surfaces */
--r-pill:       999px;   /* tags, chips, nav containers, status. NEVER a submit control. */
--r-sheet:       28px;   /* OVERLAY PLANE ONLY — modals, mobile sheet. Concave notch = 28px,
                            one per screen. No notches on page bands: the cream→cream-gold
                            boundary is a ~3% luminance step and a notch cut across it is
                            invisible. This is why seven notch proposals were rejected. */
--r-none:         0px;   /* RESERVED. Dev-only chrome. Never ships. */
/* retire the 6px step */

/* ─── TYPE ───────────────────────────────────────────────────────────── */
--t-display:  56px/1.05;  /* hero H1, hero stat values */
--t-h1:       40px/1.10;  /* chapter bands — max 4 per page */
--t-h2:       28px/1.15;  /* sections inside a band */
--t-h3:       20px/1.30;  /* card titles — MUST outrank body */
--t-body-lg:  18px/1.60;  /* leads */
--t-body:     16px/1.60;  /* FLOOR for all sentence copy. Kills every 14px body. */
--t-caption:  13px/1.40;  /* ABSOLUTE FLOOR. Kills every 9–12px corpus import. */
--t-micro:    11px/1.20;  /* eyebrows, chips, stat labels. +0.08em, caps. */

/* ─── SPACING ────────────────────────────────────────────────────────── */
--gutter:        20px;   /* horizontal gap = vertical gap = inner padding. Invariant. */
--pad-page:      48px;   /* 24 at md, 16 at sm */
--container:   1280px;
--band-y:        96px;   /* 56 at md */
--shadow-card:  0 2px 8px rgb(46 27 69 / .05);
--shadow-float: 0 8px 32px rgb(46 27 69 / .12);
--scrim:        linear-gradient(180deg, transparent, rgb(46 27 69 / .55));
```

**Three cross-cutting laws that are not tokens:**

- **Numbers** (S16) — value ≥ 2.5× its label; Manrope tabular with Indian digit grouping, always; exactly one accented cell per view.
- **Type voice** (S19) — Lora for human sentences, Manrope for every number and every control, zero overlap; serif never below 16px and never inside a control. ⚠️ **Prerequisite:** `app/layout.tsx` loads Lora `style: ['italic']` only, exposed as `--font-serif-italic`. Add the roman weights and a `--font-serif` token, or this law renders every credential and wordmark in italic.
- **The compound CTA** (S10) — a pill with a circular icon button set into its own end cap. The corpus calls it "the most reliably reusable component in the set; copy it exactly." It is *the* primary button, everywhere. Secondary is always a text link with an icon — never a 30%-opacity outline (`border-cream/30` measures 2.55:1 and fails WCAG 1.4.11).

**And two structural traps that are not plates:** *concave notches on page bands* — every corpus notch crosses a 40+ point luminance boundary, while every boundary here is 2–4%, so the notch is invisible and the reflow cost is pure loss; and *inverted rows for static taxonomy* — inversion is a selection-state device, and applying it to EULA permission lists, cancellation fee ladders or a persona menu where nothing is ever selected encodes meaning in surface luminance alone.
